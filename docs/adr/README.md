# Architecture Decision Records (ADRs)

This folder stores short, durable decision notes for changes that have
long-term impact or significant tradeoffs. Use ADRs to explain why a decision
was made, not just what changed.

## When to add an ADR

- A decision affects multiple components or future work.
- A decision has meaningful tradeoffs or likely future debate.
- A decision changes the system's architecture or workflow shape.

If you check the ADR box in the PR template, add one ADR file here.

## Naming

Use a simple sequence or date prefix:

- `0001-<short-title>.md`
- `2026-02-11-<short-title>.md`

## Template

```markdown
# Title

Date: YYYY-MM-DD

## Context

## Decision

## Consequences
```
